# cx 中文说明

## 1. 工具的作用

cx 是面向 Codex 工作流的本地命令行输出压缩工具，不是 Agent Skill。它运行真实的开发命令，但会按命令类型保留测试结果、错误、Git 变更和其他决策证据，减少日志、搜索和构建输出进入模型上下文的 token。

它不会盲目截断输出：原始失败输出会保存到本地缓存，命令退出码保持不变，并记录压缩前后的 token 使用量。

## 2. 使用场景

- 测试、构建或 lint 命令产生很长的日志。
- 查看 Git diff、状态、搜索结果或进程列表时输出过多。
- 希望减少 Codex 阅读工具输出时的 token 消耗。
- 需要保留命令成功/失败判断，同时压缩无关噪声。

## 3. 使用方法

安装后可在终端中使用 `cx` 包装开发命令。常用方式示例：

```bash
cx test
cx git diff
cx rg "TODO" src
```

先用以下命令确认安装：

```bash
cx --version
```

要让 Codex 在工作中自动优先使用 `cx`，还需要在全局或项目的 `AGENTS.md` 中增加团队认可的调用规则。该规则会影响 Agent 之后执行命令的方式，建议先确认实际项目的测试、构建与搜索命令后再配置。

## 4. 安装方法

```bash
npm install -g @contextlimit/cx
cx --version
```

本机已安装版本：`cx 0.1.1`。

如 npm 的全局 bin 目录未在 PATH 中，可将对应目录加入 shell 配置；本机已在 `~/.zshrc` 中加入 Node 全局 bin 路径。

## 5. 是否收费

- 工具免费，采用 MIT 开源许可。
- 它本地运行，不需要单独 API Key 或订阅。
- 使用 cx 后，Codex 的订阅或模型用量仍按账户方案计算；cx 的作用是降低进入模型的工具输出 token。

## 注意事项

- cx 不是 OpenAI 官方产品。
- 首次接入真实项目时，先用在只读命令、测试和日志分析上，确认输出满足需要后再写入 `AGENTS.md` 自动化规则。
- 遇到失败时，可从 `~/.cx/cache/failures` 查看完整原始输出。
