# Skill Creator 中文说明

## 1. Skill 的作用

`Skill Creator` 是 OpenAI 提供的 Skill 创建与维护指南，用于把可重复的任务流程沉淀成能被 Codex 自动发现和调用的独立 Skill。

一个 Skill 的核心是 `SKILL.md`，可按需包含：

- `scripts/`：需要稳定、可重复执行的脚本。
- `references/`：API 文档、业务规则、表结构等按需读取的资料。
- `assets/`：模板、图片、字体或其他交付物资源。
- `agents/openai.yaml`：在 Codex 界面中展示的名称、简介和默认提示语。

它重点解决四件事：定义准确的触发条件、让步骤与任务复杂度匹配、控制上下文长度，以及通过实际任务验证 Skill 是否可用。

## 2. 使用场景

- 某项工作会反复执行，例如竞品调研、日报整理、选品、文档生成或数据清洗。
- 希望将公司 API、数据库结构、业务规则或团队流程沉淀给 Codex 使用。
- 要创建带脚本、模板、参考资料的专业 Skill，而非只写一段提示词。
- 已有 Skill 的触发不准确、内容冗长或执行不稳定，需要更新和验证。
- 需要把个人经验或团队最佳实践标准化，降低每次重新说明需求的成本。

不适合的情况：

- 只执行一次且没有复用价值的临时任务。
- 把通用常识或大段无关背景资料塞进 Skill；这会占用上下文并降低触发质量。

## 3. 使用方法

### 创建新 Skill

直接向 Codex 描述重复任务和预期交付物。例如：

```text
帮我创建一个“竞品价格监控”Skill：
输入竞品网址后，提取套餐、价格和主要功能；
结果保存为 Markdown，并输出与上一次的差异。
```

Skill Creator 的标准流程是：

1. 用具体例子确认 Skill 要完成什么、何时触发、输出给谁使用。
2. 规划是否需要脚本、参考资料和素材。
3. 用初始化脚本创建目录骨架。
4. 编写 `SKILL.md` 与必要资源。
5. 运行快速校验，并用真实任务迭代。

### 初始化目录

```bash
python3 ~/.codex/skills/skill-creator/scripts/init_skill.py \
  my-skill \
  --path ~/.codex/skills \
  --resources scripts,references
```

生成 Skill 后，应补充准确的 YAML frontmatter：

```yaml
---
name: my-skill
description: 说明此 Skill 做什么，以及在什么任务或关键词下应使用它。
---
```

名称应使用小写字母、数字和连字符，例如 `competitor-price-monitor`。

### 校验新 Skill

```bash
python3 ~/.codex/skills/skill-creator/scripts/quick_validate.py \
  ~/.codex/skills/my-skill
```

校验通过后，还应使用一两个真实请求测试触发是否准确、步骤是否完整、输出是否符合预期。

### 设计原则

- `SKILL.md` 保留核心步骤；较长的资料放到 `references/`，按需加载。
- 多种可行做法时给出原则；流程脆弱或易出错时提供具体脚本和少量参数。
- 描述中要同时写明“做什么”和“何时使用”，因为这是 Codex 的主要触发依据。
- 不要额外创建与执行无关的 README、安装说明或变更日志，避免 Skill 目录膨胀。

## 4. 安装方法

Codex 默认已内置系统版 `skill-creator`。本机已按用户 Skill 额外安装 OpenAI 官方副本，位置为：

```text
~/.codex/skills/skill-creator
```

从 OpenAI 官方仓库安装的命令是：

```bash
python3 ~/.codex/skills/.system/skill-installer/scripts/install-skill-from-github.py \
  --repo openai/skills \
  --path skills/.system/skill-creator \
  --name skill-creator \
  --method git
```

安装完成后，重新打开或新建一个 Codex 对话，使新安装的用户副本被加载。

官方仓库：[openai/skills](https://github.com/openai/skills)
