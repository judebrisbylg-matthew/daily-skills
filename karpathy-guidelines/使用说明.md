# Karpathy's Guidelines 中文说明

## 1. Skill 的作用

`karpathy-guidelines` 是一组降低 AI 编码常见错误的行为准则。它基于 Andrej Karpathy 对 LLM 编程问题的公开观察整理而成，不是 Karpathy 本人发布的软件或官方工程标准。

该 Skill 通过四项原则约束编码过程：

- 先思考：明确假设、不确定项和可选方案，不在模糊需求下自行猜测。
- 保持简单：只写解决当前需求的最少代码，不添加未被要求的功能或抽象。
- 小范围修改：只修改与请求直接相关的文件和代码，不顺手重构无关部分。
- 可验证交付：将任务拆为可检查的目标，并通过测试、构建或其他证据确认结果。

它的取舍是偏向谨慎和可控，而非追求最快速度；对于非常简单的任务，应避免把流程套得过重。

## 2. 使用场景

- 修复 Bug，希望先复现问题、再最小化修改并验证修复。
- 给现有项目增加小功能，避免 AI 趁机引入不必要的配置、抽象或大规模重构。
- 进行代码审查，检查改动是否超出需求范围。
- 重构代码，需要保证改动前后的测试结果一致。
- 需求存在歧义时，希望 Codex 先说明假设、风险和更简单的可选方案。

不适合的情况：

- 只需要一次简单文本回答、翻译或不涉及代码的任务。
- 创意探索初期需要快速尝试大量方案的任务；此时过早限制实现范围可能降低探索效率。

## 3. 使用方法

安装后，在编写、审查或重构代码时，Skill 会在相关任务中自动提供约束。也可以在需求中主动强调：

```text
按 Karpathy's Guidelines 修复这个问题：
先说明复现条件和假设；只改必要代码；
补充能验证修复的测试，并报告测试结果。
```

### 四项执行规则

1. **编码前先思考**：不确定时应说明问题并提问；存在多种解释时不应静默选择其一。
2. **优先简单方案**：不增加未要求的能力；一次性代码不要为未来假想需求建立抽象层。
3. **进行外科式修改**：保留既有代码风格；不修改无关格式、注释或旧代码。只清理由本次改动造成的无用引用和变量。
4. **用目标驱动验证**：将“修复”“新增校验”“重构”等模糊要求转为测试、构建或行为检查，并在完成前实际运行。

对于多步骤任务，可要求 Codex 先列出简短计划及每一步的验证方式：

```text
1. 复现输入校验问题 -> 验证：新增失败测试
2. 只修改校验逻辑 -> 验证：失败测试转为通过
3. 运行现有测试 -> 验证：无回归
```

## 4. 安装方法

本机已安装到：

```text
~/.codex/skills/karpathy-guidelines
```

通过 Skills CLI 安装：

```bash
npx skills add szkocot/andrej-karpathy-skills@karpathy-guidelines
```

也可使用 Codex 的安装脚本：

```bash
python3 ~/.codex/skills/.system/skill-installer/scripts/install-skill-from-github.py \
  --repo szkocot/andrej-karpathy-skills \
  --path skills/karpathy-guidelines \
  --name karpathy-guidelines \
  --method git
```

安装后重新打开或新建一个 Codex 对话，使其被加载。
